## Traced execution boundaries

Gateway `config/index.ts` owns environment parsing. `v2-services.ts` passes OTP, QR and bank secrets/salt to pure Core configuration, and chooses real versus unconfigured payment and email adapters. The read-only inspection imported configuration/payout-gate helpers only; it did not import/build the service registry or app.

For Firestore, all three Razorpay values are needed to construct the real provider; otherwise `UnconfiguredPaymentProvider` fails operations with 503. The existing `paymentProvider` readiness result checks configuration presence only. The webhook receiver is `POST /api/v2/webhooks/payments/razorpay`, registered by the V2 manifest. It verifies raw-body HMAC before service work and has no fallback secret. Capture, refund and dispute payload handling is source-traced, not newly provider-verified.

`ResendEmailSender` suppresses sends without a key in development, while production send methods throw. Transactional development suppression can return a `dev-*` message ID; that is **not delivery**. Starting a connected development worker with a missing email key could process persisted outbox work without real email. Keep workers off until delivery configuration and the appropriate packet are authorized. No outbox was drained here.

Bank encryption is AES-256-GCM with scrypt-derived key and organization-bound additional authenticated data. Source can read ciphertext under the published legacy fallback when configured-key decryption fails. This does not make arbitrary key rotation safe: the code has no general key-version ring for any previous custom key. No bank data was loaded and no re-encryption/migration ran.
