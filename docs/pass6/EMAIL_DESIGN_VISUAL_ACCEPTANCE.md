# Pass 6 transactional email design system and preview inventory

**Status:** Founder visual approval remains pending. A previously authorized V2 batch produced ambiguous Resend outcomes for the purchase receipt and ticket invitation, with no provider request IDs returned; four other variants were not attempted. Do not retry those messages without checking Resend.

**Rendering:** All 43 in-scope V1 message variants below were generated through the actual Pass 6 transactional email consumer using synthetic fixtures and an in-memory capture sender. Waitlist email is excluded from V1. No staging or production data was used.

**Visual direction:** Near-black canvas, high-contrast white typography, restrained C1RCLE orange, open event artwork, editorial family labels, stronger spacing, unboxed ticket details, a full-width primary action, and receipt-like financial rows. The Posh PDF informed information order only; its branding, QR, and attachments were not copied.

## Review notes

- Assignment, transfer invitation and resend triggers share the same canonical invitation template; one invitation design is listed.
- Transfer acceptance renders the separate current-holder and former-holder messages.
- KYC has 12 role/state combinations: Host, Venue and Promoter, each for submitted, changes requested, approved and rejected.
- Event artwork is referenced only from synthetic fixtures. Missing artwork leaves no broken-image placeholder.
- No QR code or attachment is included. Ticket state remains in the C1RCLE Wallet.
